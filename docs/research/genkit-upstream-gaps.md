# Genkit Dart upstream gap analysis

Source: read-only mining of https://github.com/genkit-ai/genkit-dart via `gh` on 2026-10-12, plus a short pass over https://github.com/genkit-ai/genkit (the JS/Go/Python monorepo, formerly firebase/genkit). Every URL below was opened or listed during this pass.

Caveat on signal strength: community engagement is very low. Only 5 of 104 open issues have any reaction at all and the maximum is 1. The highest comment count on any issue is 5. Most issues are filed by maintainers or contractors (pavelgj, kevmoo, cabljac, adesinah) as work trackers. Reaction/comment counts are therefore weak; the strongest signals are the maintainers' own tracker issues, the spike reports, and the closed-unmerged PRs. Counts are written as (r=reactions, c=comments).

## Maintainer pushback / declined directions

- Native Ollama plugin: rejected after a full 5-PR series. "Closing this series. Looking back through the earlier discussion docs, compat was the proposed plan anyway, so a standalone plugin cuts against that direction." Concedes compat cannot express numCtx/topK. https://github.com/genkit-ai/genkit-dart/pull/305
- First-party on-device plugin: declined after spike; recommendation is to point at the community `genkit_flutter_gemma`. On-device work was itself a Google request that pushed firebase_ai work out of v1. https://github.com/genkit-ai/genkit-dart/issues/384, https://github.com/genkit-ai/genkit-dart/issues/380
- Firebase AI plugin: "Deprioritised per Google request (Aug 2026)... Not in the v1 - stable milestone." https://github.com/genkit-ai/genkit-dart/issues/380
- Upstream canary CI for firebase_ai: "Not doing this." (only NOT_PLANNED issue in the repo) https://github.com/genkit-ai/genkit-dart/issues/595, PR https://github.com/genkit-ai/genkit-dart/pull/616
- Schema-library decoupling: natebosch skeptical third parties would implement a shared interface; PoC PR left in draft since March. https://github.com/genkit-ai/genkit-dart/issues/222, https://github.com/genkit-ai/genkit-dart/pull/227
- Grouping `generate()` parameters into option objects: maintainer prefers current flat API. https://github.com/genkit-ai/genkit-dart/issues/255
- MCP OAuth 2.1 client: "This is a lot of auth code... I'm not sure if it's something we want to maintain"; tried to upstream to package:oauth2. https://github.com/genkit-ai/genkit-dart/pull/186
- OpenAI Responses API: blocked until JS design lands; Dart follows JS as parity reference. https://github.com/genkit-ai/genkit-dart/issues/372

## Roadmap implications for a competing framework

1. RAG stack (retriever/indexer/reranker + local vector store) is entirely absent in Genkit Dart.
2. First-party on-device inference (C++ core) with structured output that works on small models by default, and validation that never touches the network.
3. First-class native Ollama/local provider with numCtx/topK and discovery, plus robust OpenAI-compat (fast failure, no blocking discovery).
4. Flutter-native client path to Gemini/OpenAI/Anthropic that is not second-class (contrast firebase_ai at 0.3.0 with ~25 open bugs).
5. Codegen-free or lightweight schema story that interoperates with Freezed/json_serializable without pulling analyzer.
6. Dart-native dev tooling that works on devices and web without a Node CLI and adb port forwarding.
7. Stable agents/session API with typed state, realtime/live voice, per-request cancellation, Retry-After, accurate token usage and context-window management.
8. Providers Genkit has stalled on: Azure OpenAI, Bedrock, Mistral, Hugging Face, OpenAI Responses API, Anthropic prompt caching.
