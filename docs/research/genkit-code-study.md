## 2. Architecture

### 2.1 Action and registry

- Everything is an `Action<Input, Output, Chunk, Init>` (G/src/core/action.dart:339) with optional `SchemanticType` schemas for input, output, stream and init (264-337). `ActionType` is an extension type over String (33-92); note `tool` serializes as `tool.v2` (91).
- `Action.run` (429-491) wraps execution in a telemetry span (`runInNewSpan`), propagates `context` through a Zone value (`#genkitContext`, line 24, 450-490), passes an `ActionFnArg` with `sendChunk`, `context`, `inputStream`, `init`, `cancel` (110-170).
- `Registry` (G/src/core/registry.dart:98) is two maps: `_actions` and `_values` keyed `/<type>/<name>` (99-100, 133-135), with an optional parent (child registries for per-call inline tools, 103-109). Values hold non-action things (`middleware`, `format`, `schema`, `defaultModel`).
- Lookup (179-204): exact key first, else split `plugin/name`, lazily `init()` the plugin, then `plugin.resolve(type, name)`, then parent.
- Dynamic action providers (MCP uses these) are addressed with `/dynamic-action-provider/<host>:<type>/<name>` keys (45-86, 258-300).

### 2.2 Plugin model

`abstract class GenkitPlugin` (G/src/core/plugin.dart:31): `name`, `middleware()`, `init()` returning actions, `resolve(actionType, name)` for lazy creation, `list()` for Dev UI discovery, `model(name)` helper. Plugins are wrapped in a list-caching adapter (registry.dart:334-364).

Weakness: `_ensurePluginInitialized` (registry.dart:111-119) checks a Set, awaits `plugin.init()`, then adds to the Set. Two concurrent first lookups can run `init()` twice (no in-flight future memoization, unlike `list()` which caches its future).

### 2.3 Streaming

- In-process: callback based. `StreamingCallback<Chunk> = void Function(Chunk)` (action.dart:94). `Action.stream` (508-545) and `GenkitAI.generateStream` (genkit_ai.dart:178-251) bridge the callback into a single-subscription `StreamController`, with no backpressure (chunks are pushed synchronously; an unlistened controller buffers indefinitely).
- Over HTTP: SSE-like framing (see section 4).
- Bidi: experimental `streamBidi` (action.dart:553-602) with `BidiActionStream.send/close` (698-727) and `generateBidi` for live models (G/src/ai/generate_bidi.dart). Reflection v2 uses JSON-RPC over WebSocket (`sendInputStreamChunk`/`endInputStream`, G/src/core/reflection/reflection_v2.dart:187-195).

### 2.4 Tool-calling loop (G/src/ai/generate.dart)

- Default `maxTurns = 5` (line 37). Exceeding it returns an `aborted` response with the history so far rather than throwing (484-496).
- Per turn: cancellation checkpoint (464-470), resolve model (497-504), apply format (506-508), resolve tools (510-517), build `ModelRequest`, compose model middleware (536-558), call model, return early if `returnToolRequests` (642-644), parse output if no tool requests (651-681), else execute tools (686-722).
- Tools execute SEQUENTIALLY in a `for` loop (1413). No parallel tool execution, no per-tool timeout.
- Each tool call is wrapped by middleware `tool` hooks folded in reverse (1442-1448), run in a Zone carrying the `ToolRequestPart` (1453-1459).
- A throwing tool aborts the whole generation as a `failed` response (1505-1516, 696-722). The error is NOT fed back to the model as a tool error result, so the model cannot self-correct. Unknown tool names also throw (1424-1429).
- If any tool interrupts, the loop stops and returns `finishReason: interrupted` with interrupt metadata stamped on the request parts (726-734, `_buildInterruptedResponse` 1332-1385). Completed sibling tools' outputs are preserved as `pendingOutput` metadata for resume (1253-1272).
- Otherwise the tool message is streamed as a `role: tool` chunk (740-748) and the next turn is a recursive call through the composed `generate` middleware (770-777). Recursion depth equals turn count.
- Duplicate short tool names are rejected (106-121).
- Error taxonomy: setup errors throw; runtime failures resolve to `failed`/`aborted` responses (comment at 471-476; helpers 324-449).

### 2.5 Interrupts / human-in-the-loop

- Restart path runs before the model is called (generate.dart:855-948): restarted tool requests are executed with `toolMap` null, so they resolve against the whole registry by name (1418-1421), not against the tools declared for the request.
- `_resolveResume` (1225-1330) requires every tool request in the last model message to have a reply or restart (throws INVALID_ARGUMENT at 1275-1279).
- For plain `generate`, messages and resume payloads are entirely caller supplied; there is no server-side binding of a restart's input to the original request. Agents add that check: `validateResumeAgainstHistory` (agent.dart:1997-2056) verifies the restart name/ref exists in history and the input deep-equals the original. It matches ANY historical request with that name/ref, not only the outstanding interrupt.
- Bidi sessions do not support interrupts at all (generate_bidi.dart:195-208, throws UNIMPLEMENTED).

### 2.6 Sessions and stores

- `SessionStore` interface (G/src/ai/agents/session.dart:105-150): `getSnapshot`, `saveSnapshot(snapshotId, SnapshotMutator)` where the mutator is a read-modify-write function (101). Optional `SnapshotMetadataReader` (152) and `SnapshotChangeNotifier` (173).
- Snapshot model: chain of `SessionSnapshot{snapshotId, sessionId, parentId, createdAt, updatedAt, heartbeatAt, status, finishReason, error, state}` (G/src/experimental_types.dart:149+). State = messages, custom (JSON, client patches via RFC6902 JSON Patch `customPatch` chunks), artifacts.
- Status machine: pending, aborting, completed, aborted, failed, expired (experimental_types.dart, `SnapshotStatus`). Detached turns heartbeat every 30 s and are treated as expired after 60 s without a beat (agent.dart:248, 253; wind-down budget 5 min at 263). Two-write abort protocol documented at agent.dart:173-241.
- Stores shipped: `InMemorySessionStore` (session.dart:371, unbounded maps at 387-388, no TTL/eviction), `FileSessionStore` (G/src/ai/agents/session_io.dart:112; flat JSON per snapshot + per-session pointer files; in-process per-file write lock map at 154-163, so not safe across processes; directory watcher with 2 s polling fallback, line 35; optional `maxPersistedChainLength`; tenant prefix via `snapshotPathPrefix`, whose return value is not validated at 166-169 while snapshot and session ids are validated at 175 and 194), `FirestoreSessionStore` in genkit_google_cloud (packages/genkit_google_cloud/lib/firestore_session_store.dart:365; sharded state, transactions, pointer docs at 326-333).
- `Session` is propagated through a Zone (`#ai.session`, session.dart:33, 341, 358).

### 2.7 Sub-agent delegation

Lives in the experimental `agents` middleware (MW/src/agents_middleware.dart, 1,134 lines + async 682 + continue 488). Options (32-83): `agents` names, `toolPrefix` (default `delegate_to`, so tools are `delegate_to_<agent>`), `maxDelegations`, `historyLength` (messages forwarded to the sub-agent; default 0 = task only), `artifactStrategy` (`inline` or `session`), `async` (background delegation with `check_background_tasks`, `wait_for_background_tasks`, `abort_background_tasks`, `continue_task` tools, 362-366). Sub-agents are resolved from the registry by name (`_resolveHandle`, ~628-660). Background task ids are `<agent>:<snapshotId>` (387-389). State is per generate() call (`_delegationCount`, caches, 582-606). No recursion depth limit beyond `maxDelegations` per call.

## 3. Typed schemas (schemantic / schemantic_builder)

- Annotation driven, build_runner required. Users write `@Schema() abstract class $User { String get name; ... }` with `part 'user.g.dart';` and run `dart run build_runner build` (packages/schemantic/README.md "Generated Schemas" section). Builder registered in packages/schemantic_builder/build.yaml (`auto_apply: dependents`, `build_to: cache`, combining builder). Class names must start with `$` (packages/schemantic_builder/lib/src/schema_generator.dart:51).
- Annotations: `@Schema(description, additionalProperties)`, `@AnyOf([...])`, `@Field(name, description, defaultValue)`, `@StringField/@IntegerField/@DoubleField` with constraints (packages/schemantic/lib/schemantic.dart:21-138).
- Runtime: `SchemanticType<T>` (schemantic.dart:143) with `parse(Object?)`, `serialize`, `jsonSchema({useRefs})` (211), async `validate()` backed by `json_schema_builder` (200-205). Dynamic builders: `SchemanticType.string/integer/doubleSchema/boolean/list/map/nullable` (239-389). BYOT bridge `SchemanticType.from(jsonSchema:, parse:)` (151-155; docs/schemantic-byot.md shows json_serializable 6.13 `createJsonSchema: true`).
- Generated classes are thin wrappers over a `Map<String, dynamic>` (`_json`), with lazy casting getters and mutable setters; example packages/genkit_middleware/lib/src/tool_approval_middleware.g.dart:22-83. `parse()` performs NO validation, it just wraps the map (same file, `parse` returns `ToolApprovalOptions._(json as Map<String, dynamic>)`). Primitive parses are bare casts (packages/schemantic/lib/src/basic_types.dart:105, 166, 265).
- `validate()` is never called anywhere in the packages' lib code (only definition at schemantic.dart:205). Consequently tool inputs from an LLM are "parsed" (action.dart:410-412) but not validated; bad arguments surface as a cast error inside the tool body when a getter is accessed, which then fails the whole generation (section 2.4).
- No generated `==`/`hashCode`/`copyWith` (no matches in schema_generator.dart).
- Pain points visible in code/docs: codegen mandatory for typed classes; silent "wrote 0 outputs" when the builder dev dependency is missing (schemantic README troubleshooting note); builder pins `schemantic: ">=1.0.0 <1.0.1"` (packages/schemantic_builder/pubspec.yaml) so runtime and builder must move in lockstep; CI must run builds in topological order (`build-gen-core`, then plugins, then testapps, pubspec.yaml melos scripts, "to avoid race conditions"); TODO about missing enum constraint support (G/src/ai/middleware/retry.dart:39); `_schema_generator` (internal) generates the core wire types from the shared Genkit JSON schema.

## 4. Wire protocol (client.dart / io.dart)

Protocol summary (the "Genkit client protocol", shared with JS/Go/Python servers):

- Transport: HTTP POST to a per-action URL (router default path `/<actionName>`, G/src/server/router.dart:84-88; exact-match routes, names may contain `/`).
- Request body: JSON `{"data": <input>, "init": <optional init>}` (client: G/src/client/client.dart:141, 356; server: G/src/server/action_handler.dart:72-83 rejects bodies without `data`).
- Unary response: `200` with `{"result": <output>}` (action_handler.dart:125-132). Trace ids returned as headers `x-genkit-trace-id`, `x-genkit-span-id` (226-229).
- Errors: HTTP status from `StatusCode.httpStatus`, body `{"code": <http int>, "status": "<GRPC_STYLE_NAME>", "message": "..."}` (action_handler.dart:237-248). Client also accepts `{"error": {...}}` and `{"error": "text"}` envelopes and falls back to HTTP-status mapping (client.dart:26-77). Non-GenkitException server errors are masked as "Internal server error" (action_handler.dart:24, 233-235).
- Streaming request: header `Accept: text/event-stream` or query `?stream=true` (action_handler.dart:56-58; client sends the header at client.dart:137).
- Streaming response: `content-type: text/event-stream`, `cache-control: no-cache` (action_handler.dart:212-221). Frames are `data: <json>\n\n` (delimiter at 23, 172-176):
  - chunk: `data: {"message": <chunk>}`
  - final: `data: {"result": <output>}`
  - error: `data: {"error": {"code","status","message"}}`; legacy servers send `error: {...}` (action_handler.dart:205-207, client.dart:183-200).
- Client disconnect cancels the server run via a CancellationController, except after settlement so detached agent turns survive (action_handler.dart:147-158).
- Agents over HTTP: one POST per turn to `<base>` (SSE stream of `AgentStreamChunk{modelChunk, customPatch, artifact, turnEnd}`, final `AgentOutput{sessionId, snapshotId, state, message, artifacts, finishReason, error}`), plus `<base>/getSnapshot` (`{snapshotId?, sessionId?, metadataOnly?}`) and `<base>/abort` (`{snapshotId}` to `{snapshotId, status}`) (G/src/server/agents.dart:55-76; G/src/ai/agents/remote_agent.dart:93-123; types at G/src/experimental_types.dart:36-112). `init` carries `{sessionId, snapshotId, state}`; `data` carries `{message, resume{respond, restart}, detach}`. Client-supplied context is rejected for remote agents (remote_agent.dart:150-159).

Client SSE parser quality (client.dart:121-246): splits only on `\n\n` (no `\r\n\r\n`), expects one `data:` line per event, ignores `id:`/`event:`/`retry:` fields, string concatenation buffer (176), no reconnection or Last-Event-ID resume, a frame without `data: ` prefix aborts the stream (202-206). `streamFlow` creates and never closes its own `http.Client` when none is passed (130). `RemoteAction.call/stream` take no CancellationToken (345-349, 404-408); `remoteModel` ignores `ctx.cancel` (G/src/ai/remote_model.dart:20-64).

Web safety: the transitive import closure of `lib/client.dart` is 13 files, none importing dart:io/dart:ffi (computed by following all relative/package:genkit/package:schemantic imports). External deps in that closure are `http` and `stack_trace` (client.dart:18, G/src/exception.dart:17). So `client.dart` and `experimental_client.dart` (20 files) are web-safe. `genkit.dart` and `lite.dart` are web-compatible through conditional imports (`dart.library.io` / `dart.library.js_interop`) in G/src/utils.dart, G/src/o11y/telemetry/telemetry_platform.dart, G/src/core/reflection.dart, G/src/ai/prompt_loader.dart.

Server security defaults: `GenkitRouter.serve` binds `InternetAddress.anyIPv4` and port `$PORT` or 3400 (router.dart:164-188); CORS optional but `CorsOptions` defaults to `allowedOrigins: ['*']` (G/src/server/cors.dart:26); no auth unless a `ContextProvider` is supplied (action_handler.dart:94-112); request body read fully with no size limit (action_handler.dart:62).

## 6. On-device / local models, tokens, context, RAG

- genkit_chrome (490 lines, 0 tests): Chrome built-in Prompt API (Gemini Nano) via `dart:js_interop` on `LanguageModel` (packages/genkit_chrome/lib/src/chrome_interop.dart:18-30). Model `chrome/gemini-nano`, capabilities `tools: false, media: false` (chrome_model.dart:25-32). Creates a NEW session per request and destroys it after (95, 154-156), replaying history as `initialPrompts` each time (59-73), so no KV-cache reuse. Joins message text parts with spaces, dropping non-text parts (63-70, 113-115). Ignores Genkit `output` schema; constraint only via `config['responseConstraint']` (comment at 20-24). Cancellation through `config['signal']` (raw JS AbortSignal), not Genkit `CancellationToken` (98-107). Usage maps `contextUsage` to inputTokens and reports outputTokens 0 (133-149). README says Chrome flags or origin trial needed and "expected to ship in Chrome 148" (packages/genkit_chrome/README.md).
- No Ollama, llama.cpp, MLC, MediaPipe, or other local-runtime plugin. The only mention is the OpenAI-compatible provider sample (testapps/openai_sample/lib/compatible_providers.dart:46: "llama.cpp, Ollama or LM Studio") via genkit_openai with a custom base URL.
- No FFI, no native code anywhere.
- No tokenizer and no client-side token counting. `GenerationUsage` only carries provider-reported counts plus `inputCharacters/outputCharacters` fields (G/src/types.dart:264-265) that core never computes. The Google GenAI generated client contains a countTokens message type (genkit_google_genai/lib/src/generated/generativelanguage.dart:1822) but no Genkit-level API.
- No context-window management, truncation, or compaction (grep of lib code for compact/summariz/truncat/contextWindow found only unrelated hits; anthropic maps `StopReason.compaction` to stop at genkit_anthropic/lib/src/plugin_impl.dart:869).
- Embeddings: yes (`defineEmbedder`, `embed()`; genkit_class.dart:537, genkit_ai.dart:268). Providers: google_genai, openai (known_embedders.dart).
- RAG: no retriever, indexer, reranker, document store, or vector store (local or remote) in any package. `GenerateActionOptions.docs` exists in the wire types (G/src/types.dart:194, 255) and is passed through (generate.dart:756), but `generate()` exposes no `docs` parameter and nothing injects documents into the prompt.

## 7. Security

- Tool permissions: none in core. Any registered tool can be invoked by name on restart (section 2.5).
- Approval: `toolApproval` middleware (MW/src/tool_approval_middleware.dart:67-97) interrupts any tool not on a static name allow-list; approval is granted by restarting with `resumed: {'tool-approved': true}` metadata (85-87). Approval is per name only (no argument-level policy, no expiry, no signature), and the flag is supplied by whoever sends the resume, so over HTTP the client self-approves. Agents verify restart inputs against history (agent.dart:1997-2056) which prevents argument tampering but not replay of an earlier request.
- Telemetry redaction: core redacts only the `auth` and `secrets` keys of the action context (action.dart:496-506). Dev-mode built-in instrumentation records full `genkit:input`/`genkit:output` on spans (G/src/o11y/direct_http_instrumentation.dart:89, 102), exported to `GENKIT_TELEMETRY_SERVER`. genkit_otel defaults are conservative: `ContentCapturingMode.noContent` unless `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` is set (packages/genkit_otel/lib/src/genai_instrumentation.dart:43-50; gen_ai_attributes.dart:117-130), `captureActionIO` off by default, tool spans off, metrics on.
- Secret handling: API keys from env vars (`GOOGLE_API_KEY`/`GEMINI_API_KEY` at genkit_google_genai/lib/src/common_plugin.dart:788; `OPENAI_API_KEY`, `DEEPSEEK_API_KEY`, `XAI_API_KEY` at genkit_openai/lib/src/provider.dart:144-185; `ANTHROPIC_API_KEY`). Pattern for Flutter is to keep keys server side and use `remoteModel`/`defineRemoteModel` with a header resolver (G/src/ai/remote_model.dart). No secret store, no key rotation.
- Prompt-injection defenses: none found (no sanitization, spotlighting, or tool-output tagging; grep for injection/untrusted/sanitize returned only unrelated hits). Skills middleware injects SKILL.md content discovered on disk (MW/src/skills_middleware.dart:98-120, frontmatter parsed by regex at 76-87). MCP tools are surfaced as normal tools.
- Filesystem middleware sandboxing (MW/src/filesystem_middleware.dart): tools `list_files`, `read_file`, `write_file`, `search_and_replace` (212, 262, 339, 354). Path resolution does a lexical canonicalize-and-contain check, then a manual symlink walk with a 40-hop style limit and containment check against the real root (109-190). Good, but check-then-use (TOCTOU) with no O_NOFOLLOW equivalent, no read-only mode, no size limits found, write tools always exposed.
- Reflection server v1 (dev only): binds loopback, scans ports 3100-3199 (reflection_v1.dart:90-111), writes a discovery file to `.genkit/runtimes/<pid-port-time>.json` (419-433). Routes `GET /api/__health`, `POST /api/notify`, `GET /api/__quitquitquit`, `GET /api/actions`, `POST /api/runAction`, `GET /api/values` (117-140) with no token and no Host/Origin check, so any local process (and potentially DNS-rebinding pages) can list and run actions. Contrast: genkit_mcp's HTTP server enables DNS-rebinding protection by default (packages/genkit_mcp/lib/src/server/transports/streamable_http_transport.dart:29-41, 85). On Android/iOS the v1 server is not started (reflection_io.dart:52-58, 97-103).

## 10. Weaknesses, TODOs, experimental flags

Explicit markers:
- TODO: G/src/ai/middleware/retry.dart:39 (enum constraint pending schemantic support); genkit_firebase_ai/lib/genkit_firebase_ai.dart:289, 441, 704; genkit_google_genai/lib/src/aggregation.dart:103 (merge streamed tool-call args), model.dart:22, 36, 130, 144, 210; genkit_otel/lib/src/genai/gen_ai_attributes.dart:63 (tool call id/description not captured).
- UnimplementedError for unsupported parts: genkit_firebase_ai/lib/genkit_firebase_ai.dart:594, 639; genkit_google_genai/lib/src/common_plugin.dart:696, 753; genkit_openai/lib/src/converters.dart:127 (unsupported role), 176.
- Not supported: interrupts in bidi (generate_bidi.dart:205); `continue_task` for interrupted sub-agent tasks (MW/src/agents_middleware_continue.dart:228); JSON-RPC batches in MCP HTTP server (streamable_http_transport.dart:415); OpenAI streaming for image media (openai_plugin.dart:888, 1039).
- `@experimental` count: genkit 28, genkit_middleware 3, genkit_google_cloud 1. Everything agent/session/bidi related is experimental (experimental.dart, experimental_client.dart, experimental_io.dart all `@experimental library`). genkit_a2ui README says "Status: experimental".

Design weaknesses worth exploiting:
1. Sequential tool execution, no parallel calls, no per-tool timeout (generate.dart:1413).
2. A tool exception fails the whole generation instead of returning an error result to the model (generate.dart:1505-1516).
3. Low default `maxTurns` of 5 (generate.dart:37); turn loop is recursion through middleware (770).
4. No input validation: schemantic `parse` is a lazy cast, `validate()` unused (sections 3, 2.4).
5. Codegen-only typed schemas with builder lockstep pinning.
6. Only a JSON output formatter.
7. No RAG primitives (retriever/indexer/vector store), no tokenizer, no token counting, no context compaction, no local model runtime beyond Chrome Gemini Nano (no tools, new session per call, no tests).
8. Callback streaming with no backpressure; client SSE parser is minimal (LF-only, single-line data, no reconnect).
9. Security: name-only approval that the client can grant, no prompt-injection mitigations, reflection server without auth or Host/Origin checks, server binds 0.0.0.0 with optional `*` CORS default and unbounded request bodies, dev traces capture full I/O.
10. Plugin init race (registry.dart:111-119); FileSessionStore locking is in-process only (session_io.dart:154-163); InMemorySessionStore unbounded.
11. Agent subsystem complexity: about 5,200 lines with heartbeat/abort/expired state machine, polling-based detached task observation (agent_core.dart:511-548), and stores that must implement read-modify-write mutators.
12. Web: dev mode throws without v2 reflection, prompts folder unsupported, no browser CI.
13. No published test utilities (fake models, recorders) for end users.
